## 自分専用のAI動画制作アプリを作ってみた
最近は自分専用のAI動画制作デスクトップアプリを開発しています。  
機能面では大体できたので、今はAIエージェントの振る舞いの改善のために実際にちょこちょこ動画を作っていきながら調整していこうという段階になりました。

今回の記事では、正直知見共有というよりは私の嬉しさ共有みたいな側面がやや強めではあるのですが、実際にどんなものを作っているのかや、その過程で感じたことなどをシェアしていこうと思います。

## 何を作っているか

私の動画制作プロセスは、企画を練る、台本を作る、スライドを作る、動画として組み立てるという大きく4ステップでやっています。  
詳しく知りたい方は昔動画でも解説したので [こちら](https://www.youtube.com/watch?v=bnZHnWLRaAQ) 。

![画像](https://assets.st-note.com/img/1774059854-VhW1LgOMwPjr432iyCIxfFuk.png?width=1200)

このプロセスでは成果物が複数の場所に分散していて、特にアニメーションや素材のために使っているCanvaの部分でやや煩雑になっていたので、これを [前回の記事で話したようなスライド作成システム](https://note.com/ai_saborou/n/n5e9b9fd0f334) 然り、しっかり作り込んで統合したい、というのが今作っているアプリケーションで目指していることです。

具体的にどんなものを作っているかをご紹介していきますと、まずこちらは構成を練る画面です。

このラインより上のエリアが無料で表示されます。

ここはそこまで工夫したところはなく、シンプルにタイトルやターゲット、ゴールといった動画の構成要素を書いていく場所です。ここでなるべく、自分なりの想いなり考え方なりの一次情報を注ぎ込みます。

![画像](https://assets.st-note.com/img/1774059862-FWbHk5XCMUc0YdxaISso1ftZ.png?width=1200)

このアプリ内で表示されている情報などは、すべて私のPCローカルでファイルとして保存されていて、以下のような形で動画ごとにひとまとめになっています。右下のチャット欄から会話すると、このファイルたちを編集してくれるようになっています。

![画像](https://assets.st-note.com/img/1774059875-UrGmZMuaVCkv9Pj2OK3oyfdD.png?width=1200)

動画ごとに関連ファイルをまとめる

基本的な構成情報が固まったら、それをもとに台本を生成してもらいます。その台本に対して自分でいろいろ書き換えたり、AIに編集してもらったりしていきます。ここでのちょっとした工夫ポイントとしては、セリフを複数のまとまりとして分割できるようなUIにしていることです。

![画像](https://assets.st-note.com/img/1774059883-AaXpLBk21QV84jC9ZoPWnG35.png?width=1200)

これで「このセリフたちで1スライド」というのを表現できるようになるので、後々のスライド生成のクオリティが想定とずれにくくなります。

逆に言うとAIをマイクロマネージメントし過ぎ感もあるのですが、この分割操作は一瞬で行えるので、これで想定するスライドのボリューム感に齟齬が出なくなるのは大きいと感じています。

そして、それでできた台本をもとにスライドを生成してもらい、自分でちょこちょこ整えていったりします。

![画像](https://assets.st-note.com/img/1774059903-RYmO4KHJQnqdPuVp6etDfckZ.png?width=1200)

こちらは以前の記事で語ったところから、そんなに大きな変化はないです。AIの表現の可能性を広げるために、アニメーションとか図の作り方を少しずつ足していっているのが主な変更点です。

そして最後、 **肝なのがこの動画の部分** です！

ここが一番実現したかった部分なのですが、以下のように動画プレビューが埋め込まれていて、再生を進めるにつれて、今どのセリフのどのスライドを表示しているのかが下の方で切り替わるようになっています。

![画像](https://assets.st-note.com/img/1774059910-dKu3rR0ZXIk9b12wSGmcU74v.png?width=1200)

これにより、動画を再生してチェックをしながらその場でどんどん修正していくというのが実現できるようになりました。

例えば、セリフ自体のテキストももちろんそうですし、スライド修正もここからすぐに（AIに生成してもらう場合は数十秒かかったりしますが）行えます。

![画像](https://assets.st-note.com/img/1774059917-CIkrlvc1OSzRGdw9LobAHxPt.png?width=1200)

今再生している箇所の読み上げテキストやスライドが修正できる

セリフとか間とかの値は即時反映できるので上のディスプレイで動画を流しながら、下のノーパソで開いているエディターでコードを修正、みたいな形でやっていました。  
一アプリで完結するのは画面スペース的にちょっと嬉しさありますね。

![画像](https://assets.st-note.com/img/1774089910-NEOsXPBS6dIrKkgLW3GoF2Rw.png?width=1200)

作業風景イメージ

そういうのもちょっとした嬉しさはありつつ、どちらかというと嬉しいのはスライドをその場で修正できることです。

今まではアニメーションや素材利用を目的としてCanvaを使っていたため、「Canvaで修正してローカルにダウンロード、更新されたスライドで再度動画を確認する」という流れになっていたので、この体験の摩擦が減るのは大きいです。

Canvaでやっていたようなアニメーションだったり画像編集だったりを自分で実装しなければならない側面はあるのですが、そこもAIで派手目でないもの以外は基本思い通りのものがシュッと作れるので、ローカルに思い切り寄せることでこういったシームレスな体験ができるのは気持ちが良いですね。

また、毎度お馴染みの話ではあるのですが、ここでの変更点も全てログに残るようにしています。それぞれのセリフでどんなテキストに変えたのか、間の秒数はどう変えたのか、スライドはどう変えたのかといった変更のログです。

すごい抜粋しますが、以下のようにbefore/afterを値ごとに保存するようにしています。

```javascript
{
  "before":{"text":"今日はAIエージェントの話をします","displayText":"今日はAIエージェントの話をします"},
  "after":{"text":"今日はAIエージェントの基本を話します","displayText":"今日はAIエージェントの話をします"},
  "changedKeys":["text"],
  "talkIndex":3
}
```

結局100%納得感を自分が抱くためには確認と修正が必要なので、今回のようなアプリを開発している訳ですが、やはり人間の介入があまりなくても最初からいい感じにしてくれるようなAIエージェントに仕上げていきたいな気持ちはあります。  
こうしたログを起点とした改善サイクルはちゃんと回していきたいですね。

## どう作っているか

詳細なハンズオンとかまではご用意できないのですが、大枠どんな感じで作っているのかというのをお話します。

このプロジェクトはデスクトップアプリとして作っていて、Tauriというツールを利用しています。

これ以外にデスクトップアプリを作れる存在としてはElectronというものが有名で、SlackやDiscordなど有名なアプリたちもこのElectronを使って作られています。

ですが、Electronはデスクトップアプリのサイズ自体が重く、そして挙動も重くなりがちという弱点が指摘されていて、それより軽量で動くものとしてTauriが昨今人気を集めています。

難しそうに聞こえるかもしれませんが、Claude Codeなどのコーディングエージェントに「 **こういうデスクトップアプリを作って！** 」と頼んだら簡単にセットアップ可能な形で作ってくれると思うので、ぜひ試してみてください。

また、このデスクトップアプリの裏側では、Claude Agent SDKというものが動いていま…した。

これは実質Claude Codeみたいなもので、プログラミングを通して、Claude Codeと同じ動作をするエージェントを起動できるものと考えれば良いでしょう。以下のようなコードで実行でき、Coworkなども内部的にはこれを使って動いています。

```javascript
query(
    prompt="このフォルダーの台本いい感じに改善して",
    options=ClaudeAgentOptions(
        allowed_tools=["Read", "Edit", "Glob"],
        permission_mode="acceptEdits",
    ),
)
```

これを使うと、Claude Codeと同じ挙動をするものが自分用にカスタマイズしたUIのアプリとして作れる訳です。

ただ、最初はこちらを使っていたのですが、今はOpencodeというものに差し替えました。

背景としまして、まず前提としてAgent SDKは実はClaudeの有料プランのアカウントを用いて実行ができ、APIキーを指定していないと自分のPCでClaude Codeでログインしているアカウントがそのまま使われます。  
つまりClaude CodeのためにClaudeを課金している人は追加の課金などなしにこのAgent SDKも(自分のPCでは)動かせる訳です。

ですが、ここで一つ問題があります。

先月にClaude Agent SDKなどで、OAuthトークン、つまりはProプランやMaxプランなどの契約で扱えるトークンを使ってClaudeにリクエストするのは禁止、と利用規約に書かれまして、英語圏で物議を醸しました。

それに対して、Claude Codeの中の人が「ドキュメントの書き直しで混乱を与えてしまった」としつつ、ローカルでの開発や実験にはAgent SDKを使ってOKだ、ビジネス提供に使う場合はAPIキーを使ってください、という旨の訂正のコメントをしました。

これを見て、自分だけの開発に閉じていたので私もClaude Agent SDKをこのサブスクを使う方式で動かしていたのですが、ただ、上記の声明からおよそ1ヶ月経った現状でもClaudeの利用規約の文言は変わっていません。

一人の社員の発言を信じるべきか、特に変わる気配がない公式の利用規約を重んじるかという点でややグレーな状態となっており、ちょっとよろしくないか〜と思い、OpenAIのサブスク利用が公式に許可されているOpencodeに置き換えてみています。  
（一応Anthropic公式に問い合わせたりはしているのですが、お返事は今のところない）

ただ、タスクによっては(特に台本作成や構成レビュー)やはりClaudeの方を使いたいな〜となるので、何が良くて何がダメなのかが早くクリアになると良いなと思います。

以上がこのアプリたちを作っていく上でやや特殊な部分で、あとはもうシンプルにバイブコーディング、欲しいものをひたすらAIに伝えまくっているだけです。

ただ、今回割とワークしやすかった前提として感じるのが、ある程度作りたいUIが自分の中で固まっていたことです。

![画像](https://assets.st-note.com/img/1774059941-VepxHknAoMqywrEzLjPaTXv2.png?width=1200)

今回アプリを作る上で、作りたいものを完全にゼロから考えたというよりは、手元のエディターとClaude Codeである程度実現したい業務を何回も行っていて、そこである程度「こういう業務が最適そうだ」という形は言語化できていました。

なので、今回そこまで詳細に仕様とかを固めずに作り始めたのですが、それでもそこまで大改修を必要とせず、そのまま自分が使いたくなるようなUIにできてきました。

作るものの規模感にもよりますが、いきなりアプリをガッツリ作るというよりは、まず手元でAIエージェントと仕事をし尽くして、「ちょっと特化したUIがあると更に便利かもな〜」と感じてから作ると良いのかもしれません。  
（というか大方の仕事ではむしろUIがある方が邪魔だなとなる気がする）

## AIエージェントの挙動のブラッシュアップはまだ地道

というわけで、大枠の機能としては大体できたのですが、正直各所でのAIエージェントの働きについてはまだまだブラッシュアップしがいがあるなといった所感です。

こういった新規のアプリを開発していて感じるのですが、機能開発は本当に爆速になりました。

このアプリに関しても大枠の機能の8割ほどは2〜3日ででき、残りは基本AIエージェントによりうまく働いてもらうための仕組み作りが主です。

このAIの挙動を着実に & 高速に改善するためにやはり **評価** は大事だなと感じていて、以前の記事で書いた通り、スキルなどが広まるにつれて、この概念を知っておくと役にたつ場面も増えてる感があるので改めて広めていきたいなと思いました。

ひとまず今回のプロジェクトでは、そこのサイクルを少しでも早めるために、UIを通して検証するのではなく、ローカルで検証用のフォルダなどを作り、そこでまずCLI経由で楽に実行・検証サイクルが回せるようにしてブラッシュアップし、それと同じものをこのデスクトップアプリからも使ってもらう、という形にしています。

![画像](https://assets.st-note.com/img/1774090766-gPAyw3MfGNC9TI7Q5n1ijqYL.png?width=1200)

ただ、こういうの整えてもエージェントが何分、時に何十分と働き続ける現実は変わらないので、1日の始まりに各検証の設計をしっかり行い、常に並列で検証が回り続ける状態を作る、仕事の仕方の設計が大事だなぁと感じています。

正直今までの人生ズボラなプロジェクト管理をして生きてきたのですが、しっかりとプロジェクトのゴールや、それを細分化して必要な条件を思考 & AIとそれを同期していくことの重要性が爆上がりしているので考え方を適合していくしかないですね。

## 専用アプリを作って思うこと

やはりこうした自分に特化したUIを持ったアプリを爆速で作れるのは良い時代になったなと感じます。  
昔だったらこれと同じものを自力で作ろうとしたら1-2ヶ月は余裕でかかっていたんじゃないでしょうか。

私が嬉しいと感じた「動画の再生に合わせてセリフが切り替わる体験」なんて、Remotion公式の機能ではないのでかなりゴリ押しした実装をしていて、AI以前なら調査だけで2-3日溶かしてもおかしくない難易度のものでしたが、今回はCodexにお願いしたら一発でした。

こうしたアプリをひたすら作り込むのは、もはやゲームみたいな感覚で中々に没入感があります。改めてですが、そういうった楽しさを伝えられる発信をしていきたいなと感じました。
