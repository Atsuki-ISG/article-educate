## 出力を安定させるコツ

### リファレンスにとにかくこだわる

Nano Banana Proでは、テキストだけでなく画像のインプットとして渡して、それに即して生成してもらうことができます。  
私の肌感ですが、このリファレンスの量を増やす、かつなるべくスタイルを均質にすることでかなり出力が安定します。

**多様性を持たせるためになるべく様々な構図のリファレンスを増やす** が(少ないと特定のレイアウトに引っ張られることがある。十分に検証できてる訳ではないですが、気持ち5件くらいあると良いです)、 **スタイル(配色、フォント)はなるべく統一する** 、というイメージです。

例えば、私が最初にリファレンスとして用意した黒板スライドたちはこの3つでした。

このラインより上のエリアが無料で表示されます。

ちょっと右上の画像のような黄色っぽいものが混ざっている結果、ちょっと違うんだよな、という出力がよく出ていました。

なので、よろしくなさそうなデータを間引いて、自分の理想に近いものだけでリファレンスを固めるようにしました。

微妙なデータは百害あって一利なし。これを取り除いて理想のリファレンスデータを組み立てることが安定した出力の鍵となるでしょう。

### プロンプトは自分で丁寧に考えるか、大量の文章を与えるかのどちらか

何が言いたいかと言いますと、中途半端な長さの文章を与えると、その文章をそのまま画像に表示してしまうケースが多くありました。

> そんな時に活躍するのが、 **配列** と **オブジェクト** です。これらは「複数のデータをまとめて扱える」という点で、これまでのデータ型とは一線を画します。いわば、 **データの中にデータを持つ** 、入れ子構造になった型なのです。  
> **配列** は、複数のデータをまとめて管理できる便利な型です。  
> **オブジェクト** は、 **キー** と **値** のペアでデータを管理する型です。実世界の辞書のように、「単語（キー）」を引くと「意味（値）」が得られるイメージです。

![画像](https://assets.st-note.com/img/1764159320-XGwUrgaVR7bl3Ff1HvNJoKxO.png?width=1200)

プロンプトテンプレートにも一応トピックの文字をそのまま使わないでねとは書いてはいるのですが、ちょっと引きづられやすくなるようです。

> 提供された参考画像と以下のトピックに基づいて、黒板スタイルの教育的なイラストを作成してください。  
> キャラクターのスタイルと黒板のスタイルを維持してください。  
> **トピックの文章をそのまま含めず、より少ない言葉でトピックを伝えるようにしてください。**  
>   
> Topic: ${prompt}

なので、これに対する回答としては、1つ目がめっちゃ丁寧に自分で出力対象の文字を厳選するパターンです。

例えば先ほど例としてお見せした貼り付けた文章は次のように短くします。

> 配列とオブジェクト: データをまとめて管理  
> \- 配列は順序付きリスト  
> \- オブジェクトはキーと値のペアでデータを管理

  

こうすると最小限の内容になってスッキリします。(ちょっとタイトルがデカくなってますが…)

![画像](https://assets.st-note.com/img/1764161710-zV7YFUDeTdjGy9aRfgI2bLrW.png?width=1200)

もう一つうまくいったパターンとしては、前後の文脈も含めて大量の文章をプロンプトに貼り付けることです。

> \### 配列とオブジェクト：データを持つデータ  
>   
> ここまで、文字列、数値、真偽値といった「単一の値」を扱うデータ型を見てきました。しかし、実際のプログラミングでは、もっと複雑な情報を扱いたいことが多くあります。  
>   
> 例えば、「買い物リスト」を管理したいとします。りんご、みかん、ぶどう...と複数の商品があるとき、それぞれに別々の変数を作るのは面倒ですよね。あるいは、「顧客情報」を扱う時、名前、年齢、メールアドレスなど、複数の情報をまとめて管理したいこともあるでしょう。  
>   
> そんな時に活躍するのが、\*\*配列\*\*と\*\*オブジェクト\*\*です。これらは「複数のデータをまとめて扱える」という点で、これまでのデータ型とは一線を画します。いわば、\*\*データの中にデータを持つ\*\*、入れ子構造になった型なのです。  
>   
> \#### 配列：複数のデータをまとめて管理  
> \*\*配列\*\*は、複数のデータをまとめて管理できる便利な型です。  
>   
> \`\`\`javascript  
> const shoppingList = \["りんご", "みかん", "ぶどう"\];  
> \`\`\`  
>   
> 配列の中の要素には、番号（\*\*インデックス\*\*）でアクセスできます。  
>   
> ここで注意したいのが、プログラミングの世界では\*\*番号が0から始まる\*\*という点です。日常生活では「1番目、2番目、3番目...」と数えますが、プログラミングでは「0番目、1番目、2番目...」と数えます。最初は違和感があるかもしれませんが、慣れていきましょう。  
>   
> \`\`\`javascript  
> const shoppingList = \["りんご", "みかん", "ぶどう"\];  
> console.log(shoppingList\[0\]); // りんご（0番目＝最初の要素）  
> console.log(shoppingList\[1\]); // みかん（1番目＝2つ目の要素）  
> console.log(shoppingList\[2\]); // ぶどう（2番目＝3つ目の要素）  
> \`\`\`  
>   
> 配列に要素を追加することもできます。配列には専用の機能（\*\*メソッド\*\*と呼びます）が付属していて、\`push\`はその一つです。\`push\`を使うと、配列の最後に新しい要素を追加できます。  
>   
> \`\`\`javascript  
> const shoppingList = \["りんご", "みかん"\];  
> shoppingList.push("ぶどう"); // 最後に「ぶどう」を追加  
> console.log(shoppingList); // \['りんご', 'みかん', 'ぶどう'\]  
> \`\`\`  
>   
> \#### オブジェクト：キーと値のペアで情報を整理  
> \*\*オブジェクト\*\*は、\*\*キー\*\*と\*\*値\*\*のペアでデータを管理する型です。実世界の辞書のように、「単語（キー）」を引くと「意味（値）」が得られるイメージです。  
>   
> \`\`\`javascript  
> const userInfo = {  
> "名前": "太郎",  
> "年齢": 25,  
> "職業": "営業"  
> };  
> \`\`\`  
>   
> オブジェクトの値には、キーを指定してアクセスします。  
>   
> \`\`\`javascript  
> console.log(userInfo\["名前"\]); // 太郎  
> console.log(userInfo\["年齢"\]); // 25  
> \`\`\`  
>   
> オブジェクトは、配列よりも構造的に情報を管理したいときに便利です。  
>   
> \`\`\`javascript  
> // 顧客情報を管理  
> const customer = {  
> "id": "C001",  
> "名前": "山田太郎",  
> "メール": "yamada@example.com",  
> "購入履歴": \["商品A", "商品B"\]  
> };  
>   
> console.log(customer\["名前"\]); // 山田太郎  
> \`\`\`

こうすると、Nano Banana Proはさすがにこのテキストを全部表示するわけにはいかないと思ってくれるのか、自分で抽象化した図にしてくれます。

![画像](https://assets.st-note.com/img/1764161858-iIfAHYDFjWQ9sySbJXmPuTgv.png?width=1200)

なので、私の今回のケースのように、本の中の挿絵を作りたい！という場合には、ある程度まとまった文章があるので、それを丸ごと貼り付けちゃう方が良さそうです。

自分で丁寧に考えるか、まるっとお任せするかの二択ですね。中途半端は良くなさそうです。(私はもうNano Banana Proに対して **私より情報要約力が高いのでは…？** と敗北感を覚えたので、丸っと貼り付ける方が多くなっています。)

### 再生成・編集

それでもちょっと惜しいところやうまくものが出ていないときは再生成をします。  
再生成・編集の方針も3パターンあります。

1. Canvaでいじる
2. 生成された画像をリファレンスに再生成
3. 丸ごと再生成

Canvaではマジック切り抜きやテキスト切り抜き機能があるので、それで特定のものを動かしたり削除したりしています。

[https://www.canva.com/ja\_jp/help/using-magic-grab/](https://www.canva.com/ja_jp/help/using-magic-grab/)

例えばこんな感じでサボルちゃんを綺麗に切り抜けたりします。(リファレンスにサボルちゃんがいると、場所が固定化される感覚があったので切り抜いてます。)

![画像](https://assets.st-note.com/img/1764506435-5avdGXNTy2F8lAZMePcYQ49x.png?width=1200)

二つ目の生成された画像をリファレンスに再生成なんですが、便利ではありつつ、うまくいかないことも多い感がありますね。

![画像](https://assets.st-note.com/img/1764506550-R2yv3aheYk8cI6NuLiKrFoz9.png?width=1200)

テキストを小さくしてって言っても全然聞いてくれない図

おそらくブラシで変更箇所を範囲指定できるようにしたり、新しいレイアウトを提案する他のリファレンスを追加する、など追加の工夫があった方が良いんじゃないかと考えています。この細かい編集をNano Banana Proでどう行なっていくかは今後研究していこうと思います。

あとはもう数撃ちゃ当たる戦法で行くのも良いという気がしています。  
お金は溶けるんですけど、まあ〜これで上手く行っちゃうことが多く…。

![画像](https://assets.st-note.com/img/1764506884-ar6qYksVQBhdo25Jl9w1MKcH.png?width=1200)

私は今まで基本LLMしか触っておらず、画像生成にはあまり詳しくないんですが、画像生成ツールたちが複数枚生成するオプションを皆備えている理由が分かります。  
どんなものを作るかによって変わってくるとは思うのですが、プロンプトを調整するよりガチャを回す方が効率が良いなという感じてしまうことが多いです。

Nano Banana ProはAPI経由だと一枚20円くらいかかるので安い！！！とは言いづらいですが、人件費と比べ出すと破格と言って良いです。  
ご自身がどれくらいの頻度で生成するのか、生成してもらった後にどんな種類の編集が必要かに応じて最適な付き合い方を模索してみると良いでしょう。

## おわりに

以上、最近Nano Banana Proで挿絵をたくさん作っていて感じたことをシェアしました。

まとめると次の通りです

- リファレンスはそれなりにあった方が良い(5枚くらいを目指す)
- リファレンスは構図は多様性を持たせ、スタイルは統一する
- プロンプトはもはや情報を余すことなく丸っと乗っける方が良いかも知れない、中途半端が良くない
- 編集ももはや丸っと再生成が楽
